# Benchmark results

The authoritative measurements live in `artifacts/benchmarks/report.json`
(generated by `make benchmark`) and in the API P95 test under
`tests/performance/`. This file only explains how to reproduce and read them; it
must never be hand-edited with numbers that were not measured on this host.

## Commands

```bash
make benchmark                 # 100 synthetic 10 s episodes, 2 CPU + 1 vision worker
uv run pytest tests/performance -q -m performance
```

## What is measured

| Measurement | Method |
|---|---|
| `GET /episodes` P95 (10,000 metadata rows, ≥500 requests, 10 concurrent) | `tests/performance/test_api_latency.py` (httpx against the app, same host DB) |
| pipeline-run creation P95 (≥200 requests) | same file |
| 100-episode end-to-end throughput | `dataops benchmark` — imports 100 synthetic ego episodes, drains the task DAG with 2 CPU + 1 vision worker threads using FakeDetector, then asserts no permanent `RUNNING` task and no duplicated output asset |
| real YOLO11n inference time | AT-21 test — records weights SHA-256, input SHA-256 and per-frame timing; no SLA is claimed |

## Reporting rules

* Results include host platform, CPU count, Python version, storage backend and
  detector mode (see the JSON report).
* If a performance budget is missed, the report shows the measured value and the
  performance item stays **not met**; numbers are never adjusted retroactively.
* Synthetic episodes are labelled `data_origin=synthetic`; the benchmark does
  not claim production-scale capability.
